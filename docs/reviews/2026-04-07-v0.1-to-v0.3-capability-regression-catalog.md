# OpenGolem — v0.1.0 → v0.3 Capability Regression Catalog

Date: 2026-04-07
Comparison basis:
- `v0.1.0` → `c5cdc28`
- `v0.3` → `c68d655`

## Executive summary

After comparing the actual Git tags, I do **not** see evidence of a broad loss of **shipped** functionality from v0.1.0 to v0.3.

Most of the important v0.1 capabilities are still present in v0.3, including:
- TUI
- Telegram
- per-group isolation
- Token Broker
- Call Inspector
- scheduled tasks
- Alef / SOUL.md behavior
- Cato inline + scheduled audit scaffolding
- health endpoint
- remote control
- shared read-only context mount (`data/extra/`)

So the correct conclusion is:

> The major problem is **not** widespread capability regression.
> The major problem is that v0.3 introduces a much richer architecture/spec layer, and the implementation is still catching up to that target.

That said, there are a few categories worth cataloging.

## 2) Capabilities from v0.1 that appear weaker, incomplete, or no longer as straightforward in v0.3

These are the closest things to real regressions, but most are better described as **weaker delivery or incomplete carry-forward**, not outright removal.

### 2.1 Security story clarity got worse before it got better
In v0.1, the system had a smaller, simpler functional surface.
In v0.3, the architecture/spec layer is much richer, but that creates a new problem:
- more capabilities are described
- not all are fully enforced end-to-end yet

This is not a feature removal, but it can feel like capability loss because the implementation now looks incomplete against its own expanded claims.

### 2.2 Some v0.1 behaviors are now only partially honored against the stronger v0.3 spec
Most important examples:
- broker-scoped execution exists, but broker-fail-closed is not consistently enforced
- Call Inspector exists, but skill whitelist and memory scope are still advisory in practice
- Cato exists, but not yet at the breadth implied by the newer architecture

These are not losses relative to v0.1 functionality.
They are cases where **v0.3 raised the bar**, and the implementation did not fully catch up.

### 2.3 Operator experience is more fragmented
v0.1 had a simpler doc/story path.
v0.3 spreads understanding across:
- `ARCHITECTURE.md`
- `PLAN_V1.md`
- `IMPLEMENTATION_AUDIT.md`
- multiple security reviews
- multiple component specs

This is not loss of runtime capability, but it is a real loss of **immediate comprehensibility**.

## 5) The short list of items I would treat as practical regressions or missing carry-forward

If you force me to produce a practical regression catalog, this is the honest short list.

### R1 — v0.1 simplicity of the operator story is gone
The system is more powerful on paper, but much less immediate to understand.
This is a documentation/operability regression, not a runtime feature regression.

### R2 — v0.1's smaller security surface turned into a larger partially-enforced architecture
Again: not a raw feature loss, but a real loss in confidence and clarity.
What once looked like a compact working system now looks like a broader target architecture with incomplete enforcement in some key places.

### R3 — Some old functionality is now preserved only as compatibility material while the canonical docs moved ahead
Examples:
- old INTERNALS / PLAN / SPECS docs archived
- current architecture points to components and contracts not yet fully realized

This can create the impression that previously concrete behavior has become provisional.

---

## 6) Bottom line

If the question is:

> "Which concrete v0.1 capabilities are gone in v0.3?"

my answer is:

> **Very few, if any, major shipped runtime capabilities are actually gone.**

If the question is:

> "Why does v0.3 feel like a loss of functionality?"

then the real answer is:

1. the architecture/spec layer became much more ambitious
2. the implementation is now being judged against that richer target
3. the docs are more fragmented and less immediately legible than v0.1
4. some important invariants are now visibly partial rather than quietly assumed

So the real catalog is not "features removed."
It is closer to:

- **runtime mostly retained**
- **architecture greatly expanded**
- **implementation/spec alignment still incomplete**

That mismatch can absolutely feel like lost functionality even when the core shipped features are still there.
